## Lessons
- A heredoc turns `\n` inside a Python string into a real newline as well as halving backslashes: any script or test text holding an escape goes through the Write or Edit tool.
- A test that finds the checkout by walking up to `Bosun.slnx` must also ask for a file only the checkout has: `build/` can hold a copy of the solution.
- Call the CI gate only after `gh run list --commit <sha>` shows the push's own run: called at once, it starts a duplicate run that queues behind the first and doubles the wait.
- Gate the commit that changed code, whose push starts its own run: a record-only commit pushed on top of an ungated code commit has no `build.yml` run of its own (the path filter), so the gate starts one after its grace and it queues behind the code commit's build (21 minutes on `2a9cb72`).
- Two code commits pushed minutes apart queue their builds one behind the other (the workflow's concurrency group), so the second gate waits for both: where a round's fix is small, gate once, on the last code commit.
- Decided 2026-11-13: after `D02 T02 §3`, the ready rows on the path to the first window (`D02 T02 §9`, then `D02 T01 §4`, `D02 T02 §1`, `§2`, `§4`) run before `D02 T02 §8` and the other ready rows, because the owner asked twice when an interface can be seen. Nothing depends on the order between them; reversing it costs nothing.
- A fixed "impossible" window handle is not impossible: `0x7FFF0FF0` was a real window's on 2026-11-14 and failed a self-test that had passed for a day. Ask Windows (`IsWindow`) for one no window has.
- Following a launch by snapshots of parent process ids loses any descendant whose parent lived between two snapshots. A job object, with the process created suspended and put in it before it runs, is the only ownership that survives the parent, and it needs no process list to stop.
- A child started with inherited handles holds its starter's output pipe open: a test that reads that pipe to the end then waits for the child's whole life (90 s here), and everything it meant to check has expired by itself.
- A control's content is its logical child and inherits what the control's style sets: put a header's colour and weight on the header's presenter, and set the theme's text colour on any stock control (`TabControl`, `TabItem`, `ListBox`) whose own style sets the system's.
- A test of a folder's rules draws the tests' own view, not the whole catalogue: the catalogue grows with every surface section.
- The weakening scan covers every unpushed commit, the operator's too: answer its signals in a commit body before the first push of a run.
- A test that raises a key or mouse event at a WPF control can still read the real devices (a button checks the real left button before Space clicks): drive a control through its automation peer off screen, and press real keys only in the attended smoke.
- `Dispatcher.InvokeAsync` keeps an exception in its task, where no crash handler sees it; post with `BeginInvoke` when a failure on the UI thread must be a crash.
- Give a listener its callback before it starts listening: one assigned after is a window in which a request is answered by nobody.
- A swallowed exception written in a commit is flagged by the weakening scan on the push: prefer a call that can't throw (`Task.WaitAny`) to a catch that hides one.
- Put a selection, or any bound property, back with `SetCurrentValue`: setting the property replaces a one-way binding, and a two-way source is not written to while WPF is reading from it, so it is told afterwards.
- `PreviewMouseLeftButtonDown` is a direct event: a test raises `Mouse.PreviewMouseDown`, which each element turns into it. A row's selection pattern is on the list's automation peer's child, not on a peer made for the row.
- WPF's component loader (`Application.LoadComponent`, every view's `InitializeComponent`) is not safe on two threads at once: tests that make views run one class at a time (`tests/Bosun.Panel.Tests/TestAssembly.cs`).
- A row's laid-out height is stale until layout runs: after a splitter's drag or key, read the height it set on the row, not `ActualHeight`.
- A window with no handle changes `WindowState` without raising `StateChanged`: update what depends on the state where it is set, as well as in the event.
- A property a view binds to before it is first set needs change notification, however rarely it changes (a page's Retry command).
- Never chain a commit and a push after a test run in one command without stopping on its exit code: on 2026-11-15 `0c0130c` went to `main` with a failing test and a message saying it passed. Run the tests, read the result, then commit.
- `File.Exists` answers no for a file that may not be looked at: read the file and take only not-found for absent.
- A setting that lives outside the panel (a registry value, a Windows switch) is read again when the person comes back to the window, and compared with what it should hold, not merely found.
- Bound every read of a file the panel did not just write, before allocating for it.
- State that Windows holds (an installed icon, a shown notification) is asked of Windows each time or confirmed by its own message, never remembered from the call that asked for it.
- Git Bash refuses a heredoc holding an apostrophe in this harness: new files with prose go through the Write tool, edits through a PowerShell here-string piped to python.
