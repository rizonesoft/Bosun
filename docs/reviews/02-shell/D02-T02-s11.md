## Part 2. Excellence

**Strongest local alternative:** Bosun’s native one-slot queue already serializes participating processes, records holders and waiters, handles cancellation, and exposes queue state to another terminal. The desktop-specific feature saves the user from wrapping each command and handles captures nested inside a smoke run. It falls short of that alternative in three concrete ways. [Queue acquisition](/D:/Bosun/src/app.cpp:185) · [Waiter records](/D:/Bosun/src/app.cpp:303) · [Cancellation](/D:/Bosun/src/app.cpp:481)

1. **suggestion** Reduce cold-start cost. Each fresh capture compiles the lock source with `Add-Type`. The candidate records about 0.8 seconds for that step alone. Target **under 100 ms of added lock overhead at p95** across 30 fresh, uncontended capture processes, while retaining one implementation for both callers. [Capture startup](/D:/Bosun/scripts/capture-window.ps1:774) · [Recorded timing](/D:/Bosun/todo/02-shell/TODO-02-application-shell.md:524)
2. **suggestion** Make a stalled run inspectable from another terminal. The desktop record identifies the owner, but the waiting processes appear only in their own output. Target **one read-only command** that reports the owner, waiter count, and oldest elapsed wait without touching the desktop. [Desktop diagnostics](/D:/Bosun/scripts/lib/DesktopLock.cs:133) · [Native waiter reporting](/D:/Bosun/src/app.cpp:303)
3. **suggestion** Make the contention tests synchronize on observable events. The crash test sleeps three seconds before killing the holder. The cancellation test observes the output-pair lock and then sleeps another 500 ms, although compilation and recovery can still precede the desktop wait. Target **zero fixed startup sleeps** in those two tests. Observe the waiter’s actual waiting line before killing or stopping it, including on a slow cold start. [Crash test](/D:/Bosun/tests/capture_window_test.ps1:126) · [Cancellation test](/D:/Bosun/tests/capture_window_test.ps1:214)
