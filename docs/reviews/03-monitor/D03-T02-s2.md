1. **P1: A scanned folder name can launch an unintended executable.** `src/Bosun.Panel/Instances/Opener.cs:88` passes the Linux path directly to `wt.exe`. `ArgumentList` handles Windows quoting, but Windows Terminal separately splits semicolons **inside arguments** into commands. Reproduce with a WSL instance running in `/tmp/project;calc.exe`, a valid directory name that can arrive through an extracted archive. Click **Open terminal** with Windows Terminal installed. The path becomes `/tmp/project`, and `calc.exe` becomes a second terminal command. The Windows branch at line 78 has the same defect. Escape data for Windows Terminal’s parser and add a regression covering semicolons. This follows from [Microsoft’s parser implementation](https://github.com/microsoft/terminal/blob/main/src/cascadia/TerminalApp/AppCommandlineArgs.cpp#L824-L950); I did not execute the payload.

2. **P2: An unavailable network folder freezes the panel during an action.** `src/Bosun.Panel/Instances/InstancesPage.cs:370` calls `Directory.Exists` synchronously on the UI thread. Returning `Task.FromResult` afterward does not move that I/O off-thread. Reproduce by scanning an instance whose folder is on an SMB share or mapped network drive, losing the server connection, then clicking **Open folder** or **Open terminal** before the next refresh. Windows can block the existence check until its network timeout; the whole panel becomes unresponsive, with no cancellation or failure feedback during that wait. Move the filesystem check off the dispatcher and bound the user-facing wait.
