# TODO workflow

`AGENTS.md` links this file so every agent reads it. The TODO tooling is this repository's own.

`todo/` is the live execution plan; format spec: `todo/README.md`. Markdown is canonical.

Core mechanics: the Implementation Order table in each TODO file is the dependency graph; a row flips to `[x]` only through `python scripts/todo-graph.py stamp`, backed by a review receipt in `docs/reviews/` that records the plan review (`--plan`), the completion review (`--completion`) and the rounds, each pass checked against the review schedule pinned in `.conclave/reviewers.toml`; `todo/implementation-plan.md` is regenerated by `plan --sync`, never ticked or edited by hand; cross-references (`§N`, `TNN §N`, `DNN TNN §N`) are bidirectional; every section declares Phase, Needs and Surface, carries a Build order with `Done when:` per step, and must be implementable with zero conversation context.

Granularity and 100% plan completeness:
- **Small, single-responsibility sections:** Never bundle multiple subsystems, dialogs, or workflows into one coarse umbrella section. Split every TODO file into small, single-responsibility sections that each deliver one coherent, testable capability.
- **Short table descriptions (`<= 88` chars):** Keep section headings (`## N. <Title>`), `Deliverable` cells in `Implementation Order`, and `Scope` cells in index tables to a concise noun phrase of at most 88 characters so raw Markdown table rows stay under 140 characters (with description cells <= 88 characters) and never wrap in raw `.md` editors. Put file paths, symbols, CLI flags, and enumerations in the section body and micro-steps, never in the heading or table cell.
- **Granular micro-step checklist items:** Every section carries 1 to 30 buildable micro-step items (typically 4 to 15 concrete micro-steps, never a 1-bullet summary stub), ending with `- [ ] Commit: <message>`. Each non-Commit item names one action, a concrete path/symbol/command in backticks, an observable `Done when:` in the same bullet, a `Cheaper substitute:` on UI and write items, and a source citation when copying behavior from the plan or SPEC.
- **100% complete development plan:** Running `process-plan` to completion must produce a 100% complete, shippable product with zero unowned surfaces, controls, settings, refusal/error paths, undo/reverse paths, or persistence read-backs. Never cap operator-requested planning and never silently drop scope.

For TODO work, use the skill in your agent's isolated skill directory (`.agents/skills/`, `.claude/skills/`, or `.codex/skills/`) that owns the step (the independent reviewer runs through `scripts/review-dispatch.py`: GPT-6 Astra for Claude and Gemini work, Gemini 4 Carbon for Codex work, on the schedule pinned in `.conclave/reviewers.toml`): capture through `add-todo`, author a file through `create-todo`, build through `process-todo-section`, stamp through `review-todo-section`, close a file through `process-todo-file`, run a phase or the plan through `process-phase` or `process-plan`, harden the tree through `groom-plan`. The lifecycle is: capture, author, validate, the one-pass plan review (its gaps fixed in the section before any code), record `Started:`, implement, run the section's gates, commit, review rounds until clean, final medium completion and excellence review, stamp on complete, or with its missing items fixed in the same cycle (`completed`) or filed as open sections (`filed`), never re-reviewed, sync the plan.

## Rules for TODO work

- **Tests prove claims:** a section's Test checkpoint must be able to fail, and is quoted, not paraphrased, in its stamp.
- **Commits:** trunk-based `main`, concise imperative messages, the section ref in the body. Commits follow logical steps within a section; review fix-loop commits append to the candidate range. Never amend a candidate under review, never bypass hooks, never force-push.

## Validation

```bash
python3 scripts/todo-graph.py validate        # graph integrity; any fault exits 2 with the reason
python3 scripts/todo-graph.py plan --check    # generated plan is current (CI runs this)
python3 scripts/todo-graph.py query ready     # dependency-safe work right now
python3 scripts/todo-graph.py query blocked   # sections waiting, and on what
python3 scripts/todo-graph.py query stats     # tree health
python3 scripts/todo-graph.py query deferred  # open and resolved deferrals
python3 scripts/todo-graph.py query plan      # plan title, phase names and every section's status, as JSON
python3 scripts/todo-graph.py query rounds    # review rounds spent per stamped section, against the cap
```

Report only commands actually run, and distinguish static evidence, test output and review proof.

## Current reviewer policy

One writer and one independent reviewer: Codex uses Carbon (Gemini 4 Carbon); Claude and Gemini use Astra. Claude is never a reviewer. New cycles run one medium plan review, one medium adversarial review, up to `schedule.max_low_rounds` low reviews (default 8), stopping on clean, then one medium completion review last. Pass `--writer-model <exact-model-version>` and keep one findings file. The dispatcher records its committed policy and actual execution outcomes. Historical receipts and in-flight cycles retain their initiating policy, reviewer and findings. Never resume an operator-paused section without explicit authorization.
